# regions

Bicep function library that resolves Azure regions: abbreviations for
resource names, paired regions and geographies. It is the canonical home of
the region lookup; the [naming module](../naming/README.md) imports the same
generated abbreviation data and re-exports `regionCode` for compatibility.

- Region abbreviations follow the
  [claranet region naming standard](https://github.com/claranet/terraform-azurerm-regions).
- Paired regions follow
  [Microsoft Learn, Azure paired regions](https://learn.microsoft.com/azure/reliability/cross-region-replication-azure).
- Geographies follow the
  [Azure geographies](https://azure.microsoft.com/explore/global-infrastructure/geographies/)
  taxonomy of the Azure region metadata.

Repository layout: `regions.bicep` and this README are hand-written;
`regions-data.bicep` (region abbreviations) and `regions.md` are generated by
`scripts/generate.py`; `regions-info.bicep` (paired regions and geographies)
and `regions-info.md` are generated by `scripts/generate_regions.py` from
curated tables in that script.

## Usage

```bicep
import * as regions from 'br/ljfio:regions:0.3.0'

param location string = 'West Europe'

var pairedLocation = regions.pairedRegion(location) // northeurope

resource resourceGroup 'Microsoft.Resources/resourceGroups@2024-03-01' = {
  name: 'rg-${regions.regionCode(location)}' // rg-euw
  location: location
}
```

Every function accepts **any Azure region form** - the AZ CLI name
(`westeurope`), the dashed form (`west-europe`/`eu-west`) or the display name
(`West Europe`), case insensitive - exactly like the `region` segment of the
naming functions.

## Functions

| Function | Description |
|---|---|
| `regionCode(region)` | Short abbreviation for an Azure region (`westeurope`/`West Europe` -> `euw`); unknown values pass through unchanged. Same semantics as `naming.regionCode`, which re-exports it. |
| `pairedRegion(region)` | AZ CLI name of the Azure paired region (`uksouth` -> `ukwest`), or an empty string for regions without a pair and for unknown regions. |
| `geography(region)` | Azure geography the region belongs to (`westeurope` -> `Europe`), or an empty string for unknown regions. |

## Behaviour notes

- `regionCode` passes anything that is not a known region through unchanged,
  so unknown regions stay usable as free-form name segments.
- `pairedRegion` and `geography` return an empty string for unknown regions
  and for the continental/country aggregates of the abbreviation data (for
  example `unitedstates`), which are not real regions.
- Some regions have no paired region (for example `italynorth`,
  `newzealandnorth`); `pairedRegion` returns an empty string for them.
- The pairing is the Azure region pair, not a resiliency recommendation by
  itself; see the
  [Azure paired regions](https://learn.microsoft.com/azure/reliability/cross-region-replication-azure)
  guidance for what the pairs are for.

## Data sources and accuracy

The abbreviation data is fetched from the claranet region naming standard
and covers every Azure region that standard lists. The paired-region and
geography tables are **curated by hand** in `scripts/generate_regions.py` -
the abbreviation source has no machine-readable paired-region or geography
data. China region pairs follow the in-country pairing of the
21Vianet-operated regions and are not listed on the Microsoft Learn page;
China regions are assigned to the `Asia Pacific` geography. Spot-check the
curated tables against the cited pages when reviewing changes to them.

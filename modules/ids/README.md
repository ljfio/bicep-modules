# ids

Bicep function library that builds fully qualified ARM resource IDs from
naming-style type keys, so consumers stop hand-writing `resourceId()` strings
or passing resource names where IDs are required.

- Type keys follow the [naming module](../naming/README.md)'s catalogue (the
  [Azure Verified Naming Utility](https://github.com/Azure/terraform-azure-avm-utl-naming)
  resource catalog), so the same key that names a resource with
  `naming.resourceName` identifies it with the ids functions.
- Provider type strings are verified against the
  [Microsoft Learn ARM reference](https://learn.microsoft.com/azure/templates/)
  at generation time: the per-type reference page must exist and its canonical
  casing must match.

Repository layout: `ids.bicep` and this README are hand-written;
`types.bicep` (type keys and provider types) and `resource-types.md` are
generated by `scripts/generate_ids.py`.

## Usage

```bicep
import * as ids from 'br/ljfio:ids:0.3.0'

// ID of a resource in the resource group this template deploys to
output storageAccountId string = ids.armResourceId('storage_account', 'stcontosodemouksshared')
// -> /subscriptions/<current subscription>/resourceGroups/<current resource group>/providers/Microsoft.Storage/storageAccounts/stcontosodemouksshared

// ID of a resource in an explicit subscription and resource group
output keyVaultAccountId string = ids.armResourceIdIn(
  subscription().subscriptionId
  'rg-contoso-demo-uks-shared'
  'key_vault_vault'
  'kv-contoso-demo-uks-shar')
// -> /subscriptions/<subscriptionId>/resourceGroups/rg-contoso-demo-uks-shared/providers/Microsoft.KeyVault/vaults/kv-contoso-demo-uks-shar
```

## Exported types

| Type | Description |
|---|---|
| `idType` | Union of all supported resource type keys (the first parameter of every ids function). |

## Functions

| Function | Description |
|---|---|
| `providerType(type)` | The ARM resource provider type for the type key (`storage_account` -> `Microsoft.Storage/storageAccounts`). |
| `armResourceId(type, name string)` | Fully qualified resource ID in the current subscription and resource group (the deployment scope): `/subscriptions/<sub>/resourceGroups/<rg>/providers/<type>/<name>`. Delegates to the `resourceId` ARM function. |
| `armResourceIdIn(subscriptionId string, resourceGroup string, type, name string)` | Fully qualified resource ID in an explicit subscription and resource group, composed by `format` string interpolation. |

## Scope: `armResourceId` vs `armResourceIdIn`

`armResourceId` delegates to ARM's `resourceId` function and resolves the
current subscription and resource group at deployment time. This makes it a
deployment-context function, which ARM restricts inside user-defined
functions and Bicep rejects evaluating while building `.bicepparam` files
(BCP452): it can be used anywhere in a `.bicep` template, but not in a
parameter file.

`armResourceIdIn` composes the same ID shape with explicit subscription and
resource group parameters instead. It is pure, so it is usable from both
templates and parameter files, and its output is unit-testable (both
functions produce identical strings for the same scope). Use `armResourceId`
when the target resource sits in the deployment's resource group; use
`armResourceIdIn` when targeting another subscription or resource group, or
from a `.bicepparam` file.

ARM user-defined functions cannot be grouped into nested namespaces, so
`ids.storage.account(...)` is not expressible; use the type key table below
instead. As with the naming module, one function pair covers every type: Bicep
inlines each imported function into the consuming template.

## Supported resource types

The full catalogue of type keys, provider types and naming abbreviations is
in [resource-types.md](resource-types.md). Only top-level resource types are
included: types whose ID is
`/subscriptions/<sub>/resourceGroups/<rg>/providers/<type>/<name>`.
